# 房间编辑器（Room Editor）

> 状态：**可用**（2026-09-10 落地）
> 入口（三个，任选）：
> 1. **标题屏按钮**「🏗 房间编辑器」——未开局也能设计
> 2. **调试台按钮**（`~` 打开调试控制台 → 「🏗 房间编辑器（F2）」）

## 一、这是什么

一个**在游戏里设计房间**的可视化工具：画格子 → 标方向 / **通口类型** / 种类 / 风险 / 张力 → 右侧**3D 预览**（建模 / 光照 / 阴影）跟着变，不用重启、不用跳层。

它解决的是「手工设计固定房间」这件事的三个痛点：

1. **看不见成果**：改完文件要重启、跳层才发现不对。编辑器内置 **3D 预览**列（点「▶ 打开预览」开启；开启后编辑停止约 0.2 秒即重建），不用了点「⏹ 关闭预览」或关掉面板（F2）就回到真实游戏。
2. **方向和种类靠脑补**：出口方向、房间种类会决定内容该怎么摆（见 §五、§六）。编辑器把二者做成**显式输入**，并把这些字段写进导出数据，而不是"事后从网格猜"。
3. **格式易错**：画布存的就是 `PrefabMap` 的**图例字符**，导出即字符图 —— 编辑器 → 字符图 → `buildPrefabFloor` 是一条单链路，不存在"两套格式对不上"。

## 二、快速开始（3 分钟）

1. 启动游戏（要预览就跑起来；只想画可以在标题屏直接点「🏗 房间编辑器」）。
2. 点标题屏「🏗 房间编辑器」按钮，或按 **F2**，或在调试台（`~`）点按钮。
3. 右侧「尺寸」填房间大小（**3~64**，含墙圈）→ 点「应用」或回车（画布四周会自动留出墙圈 + 2 格门槽外圈）；也可用 5×5 / 7×6 / 9×7 / 11×9 / 16×12 预设。
4. 左侧「地形」选**墙**，拖拽把房间围起来；选**空地**刷出可行走区。
5. 在画布上方「**通口类型**」选一个预设（**单口 / 上下通口 / 对角通口 / T型通口 / 四方通口**），一步开关北 / 东 / 西出口；也可点四边的「北门 / 东门 / 南门 / 西门」开关手动微调（手动改后会自动显示「自定义」）。出口会在画布上亮起金色描边，墙外自动出现虚线走廊门槽。
6. 「入口」选玩家进房方向 → 画布上出现 `↑` 起点标记（**南门是固定入口**）。
7. 「种类」选房间类型（战斗房 / 宝箱房 / …），按需设「风险」与「张力」（张力为**自定义数字输入**，见 §六）。
8. 左侧「实体」刷怪、宝箱、火把等；**右键任意格固定涂成空地**（快速清障，与当前工具无关）。
9. 点右侧「**▶ 打开预览**」开启 **3D 预览** —— 开启后每次改动约 0.2 秒后自动重建，所见即所得；点「⏹ 关闭预览」收起。
10. 按 **F2** 关闭面板回到真实游戏；满意后点「复制代码」，把导出的 `roomDef` 粘贴进工程（见 §七）。
11. 需要留档时点「保存到文件」：写入 `src/data/rooms.json` 并同步生成可读摘要 `docs/房间设计笔记.md`。

> 草稿会自动存：点「保存草稿」写入 `localStorage`（键 `motarpg_room_editor_draft`），下次打开编辑器自动恢复。

## 三、界面说明

面板是一个**浮动窗口**（默认约为屏幕的 93vw × 88vh，不等于铺满），四周留有游戏画面；**拖标题栏移动、拖右下角缩放、双击标题栏复位**。

```
┌─ 头部（可拖动）：新建 / 载入草稿 / 保存草稿 / 关闭 ─────────────────────────────┐
│ 左栏：地形/实体/工具/方向语义 │ 中栏：通口类型 + 门开关 + 网格画布 │ 预览列：3D（可开关） │ 右栏：属性 + 导出 │
└─ 底部状态栏：操作反馈与错误 ─────────────────────────────────────────────────┘
```

四列栅格的最小宽度合计约 888px，面板再窄时整体横向滚动 —— **3D 预览列不会被裁掉**（这是上一版窄窗口下「看不见预览」的修复点）。

### 3.1 左栏 —— 调色板与工具

- **地形**：空地 / 墙 / 柱子 / 悬崖
- **实体**：怪物 / 精英 / 宝箱 / 大宝箱 / 遗物箱 / 楼梯 / 入口 / Boss / 火把 / 地毯 / 药水 / 治疗泉 / 商人 / 女巫 / 铁匠 / 引导者 / 大锅 / 药架
- **工具**：
  - `✎ 画笔`：左键单击格子；**按住拖拽连续画**
  - `⌫ 橡皮`：擦成默认值（房间内部→空地，边框→墙）
  - `⛏ 取色`：点格子把该字符设为当前画笔（改一处分格调色）
- **鼠标右键**：**无论当前工具是什么，右键都固定涂成空地**（按住可连续涂）；用于快速清出可行走区 / 擦掉误放的墙与障碍。画布已屏蔽右键菜单。

### 3.2 中栏 —— 画布

- **通口类型**（画布上方下拉）：**单口 / 上下通口 / 对角通口 / T型通口 / 四方通口**。点选 = 一步批量开关北 / 东 / 西出口（南门恒开）；之后手动改方向会自动显示「自定义」。判定只看**全部门（含入口）的边关系**，与入口方向无关（见 §五.5）
- 网格由**三层**组成（从外到内）：`门槽外圈(2 格)` → `墙圈(1 格)` → `可行走区`
- **金色描边格** = 门（出口）所在格；**虚线格** = 导出时自动补的走廊门槽
- 画布坐标与导出的 `rows` 一一对应：`rows[y][x]` 就是画布第 y 行第 x 列的字符
- **缩放与滚动**：打开/改尺寸时按**画布列的实际宽度**自适应格边长（10~26px）；也可用 `−` / `＋` 手动调档，`自适应` 复位。画布超出可视区时自动出现滚动条（如 64×40 会缩到 10px/格并滚动）

### 3.3 右栏 —— 属性

| 字段 | 作用 |
| :--- | :--- |
| 种类 | 房间类型（`RoomType`）。决定内容规范，见 §六 |
| 名称 | `PrefabRoomDef.name`（提示/调试用） |
| 尺寸 | 房间矩形大小（**含墙圈**，**3~64**）；改完点「应用」或回车保留重叠区域；越界会报错并回填当前值（不静默夹取）；下方有 5 个常用尺寸预设 |
| 入口 | 玩家从哪边进房 → 写入 `RoomData.fromDirection`；画布上打 `↑` 标记（南门固定） |
| 风险 | 1~3 档（倍率直接取自 `mapGeneration.content.risk.rewardMul`）；标了以后房内普通宝箱按该倍率结算 |
| 张力 | 房间级**张力值**，改为**自定义数字输入**（见 §六）。留空 = 跟随房型（取 `mapGeneration.tension.weights[type]`），也可填任意数值精细划分；是**后续「房间类型决定」**的输入维度 |
| 备注 | `PrefabRoomDef.note`，写设计意图（运行时忽略） |

### 3.4 导出与 3D 预览

- **3D 预览（默认关闭）**：点标题栏「▶ 打开预览」（或占位层里的同名按钮）开启 —— 开启后编辑停止约 0.2 秒自动 `buildPrefabFloor(def)` → `FloorManager.enterPrefabFloor()` → 相机吸附到入口；再点「⏹ 关闭预览」收起（只收起 3D 视口，编辑器面板与编辑状态保留）
- 「复制代码」：导出完整的 `PrefabMapDef`（含 `rooms` 与 `rows`；`pattern` 由出口判定后写入，`tension` 仅在显式标注时出现）
- 「复制字符图」：只导出 `rows`（粘进既有 def）
- 「保存到文件」：存进 `src/data/rooms.json`，并同步生成 `docs/房间设计笔记.md` 摘要（含**通口类型**与**张力值**：显式标注 / 房型默认）

## 五、方向语义（**出口不同 → 布局不同**）

这是本编辑器存在的核心理由。同一个房间矩形，**门开在哪条边**决定了玩家的「进入侧 → 去路」，进而决定内容该怎么摆。

### 5.1 门是怎么被认定的

`PrefabMap.buildRooms` 的判定是：

> **房间边界上的空地格，且房外相邻格也是空地 → 门**

所以「墙上开个洞」并不够，洞外面还要有路。编辑器因此在你勾选某边门时：

1. 自动把**该边中点**的边界格开成空地；
2. 导出时在墙外自动补 **2 格走廊门槽**（`TEMPLATE_MARGIN`）。

这样 `buildPrefabFloor` 一定认得这道门（契约测试对四个方向逐个验证了「入口可达墙外门槽」）。
若你手改了网格导致声明与实际不符，`PrefabMap` 会打印 `[Prefab] 房间 … 声明出口「x」但网格上无对应门口` 之类的警告 —— **方向是设计输入，不该只是事后观察**。

### 5.2 门位 → 主路径 → 摆位（核心对照表）

> 本游戏的战斗是**撞触触发**（没有"激怒/仇恨"系统），因此「必须打掉才能过」只能靠**位置门控**：把守军/屏障放在玩家绕不开的位置。

| 门位（入口 → 出口） | 主路径走向 | 屏障 / 守军应放 | 理由 |
| :--- | :--- | :--- | :--- |
| 西 → 东（对称穿堂） | 横穿 | **竖线**封在中列（`x = 中线`） | 阻断横穿；玩家只能正面突破 |
| 南 → 北（对称穿堂） | 竖穿 | **横线**封在中行（`y = 中线`） | 同上，方向旋转 90° |
| 西 → 北（L 形拐角） | 先东后北 | 拐点外侧 1~2 格（东北角前） | 卡住拐角，绕不开 |
| 对角（西南 → 东北） | 斜向 | 两条平行线各封一半，**中段留 1 格击杀缺口** | 单一朝向的封线切不断斜向路线 |
| 单门（死路房 / 宝箱房） | 进门 → 目标物 | 只守目标物前 1~2 格，**不要全房封堵** | 全封会把小房变成迷宫，且没有第二出口时毫无意义 |

**示例 A：西门 → 东门（7×6，含墙圈）**
> 下面两张图是**示意用符号**（`#`墙 `·`空地 `M`怪），不是导出字符；导出用 §四 的图例。

```
#######
#·····#
·  M  ·   ← 左右边界中点是门（`·`）
#··M··#
#··M··#
#######
```

**示例 B：南门 → 北门（同一矩形，仅门位不同）**

```
###·###   ← 北门
#·····#
#MMM M#
#   M #     ← 南门（底边中点）
#·····#
#######
```

同样的房间、同样的怪物数量，**屏障朝向完全不同** —— 这就是"出口不同要分别设计"。

### 5.3 入口方向（`entry`）

- 决定玩家进房的**第一格**（编辑器会在该侧门的内侧格打 `S` 标记）
- 写入 `RoomData.fromDirection`，供后续系统（主路径推导、报点、未来的守军朝向 AI）使用
- 与出口不必对称：**西进东出**是穿堂房，**西进西出**是折返房（玩家会原路返回，适合埋伏型/风险型设计）

### 5.4 硬性红线（踩了就出 bug）

| 红线 | 原因 |
| :--- | :--- |
| **门内侧格不放阻挡物**（柱子 / 大锅 / 药架 / `x` 悬崖） | 直接封死房门，玩家进不去 / 出不来 |
| **门内侧 2 格内不放怪** | 违反「怪物距入口 ≥3 格」的既有规则（`monsterMinDistFromEntry`），进门即战、退无可退 |
| **封堵线必留击杀缺口** | 屏障整条线全是柱子 = 该层被截断（自动生成房靠"让路怪"机制保证，手工设计要自己留） |
| **楼梯不要贴门内侧** | 从门进来第一格就踩到楼梯 = 直接掉层，跳过了整间房 |

### 5.5 通口类型（`pattern`）——「房间类型 + 通口」是从手工房间库抽取的键

同一个房间矩形，**有几条边相通、如何相通**（即"通口类型"）会彻底改变走线与守军摆法。
编辑器把它离散成 5 种**通口类型**（判定只看全部门 —— 含入口 —— 的**边关系**，与入口方向无关）：

| 通口类型 | 出口数 | 判定（全部门的方向关系） | 走线特征 | 设计要点 |
| :--- | :--- | :--- | :--- | :--- |
| **单口** `single` | 1 | 只有入口（无其他出口） | 进门 → 目标物 → 原路返回 | 死路房 / 宝箱房 / 休整房；只守目标物前 1~2 格 |
| **上下通口** `vertical` | 2 | 一对**对边**（南北 或 东西） | 贯通 / 穿堂 | 屏障垂直于走线，封中列 / 中行 |
| **对角通口** `diagonal` | 2 | 一对**邻边**（如南+东） | L 形拐角 | 卡拐点外侧；纯单线切不断斜向路线 |
| **T型通口** `tee` | 3 | 3 条边 | 一进两出 / 三岔 | 主路径选"更难的那条"，或让侧支通向宝箱 |
| **四方通口** `cross` | 4 | 4 条边 | 十字穿行 | 中心放关键物（宝箱 / Boss），四向皆敌 |

- **落地**：编辑器导出时写入 `pattern`；`buildRooms` 在未显式给出时**由网格实际门口反推**，写进 `RoomData.pattern`。
- **用途**：`pattern` 与 `type`（+ 入口方向）一起构成「**从手工房间库抽取**」的键 —— 生成楼层时按「房间类型 + 通口类型」挑房；同一类型 + 同一通口可有多间（用**张力值**区分体验），这正是"同样类型也有不同体验"的来源（见 `src/map/RoomLibrary.ts`）。

## 六、房间种类规范（**考虑种类**）

每种 `RoomType` 在自动生成房里有明确的内容契约（见 `docs/已完成.md` §10.6）。手工设计**不强制**由 `ContentFiller` 校验，但**应当遵守同样的原则**，否则体验会断裂。

| 种类 | 内空间参考（画布尺寸） | 必备要素 | 禁忌 | 建议风险 | 张力默认（`tension.weights`） |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `combat` 战斗房 | 5×4 ~ 7×5（画布 7×6 ~ 9×7） | 屏障/守军**挡在入口→出口的主路径上**；0~1 宝箱；≥1 火把 | 把怪全堆在墙角（玩家可直接绕过） | 2 | +1 |
| `elite` 精英房 | 7×5 ~ 8×6（画布 9×7 ~ 10×8） | **≥1 只精英在主路径上**；护卫 1~2；宝箱 1~2 且有人守 | 精英放角落 / 被柱子围出可绕通道 | 2~3 | +2 |

### 6.1 张力值（`tension`）——为「房间类型决定」预留的数据维度

`tension` 是**房间级**的张力贡献，与 `mapGeneration.tension.weights` **同一尺度**（正=加压 / 负=泄压），
和 `FloorGenerator` 的运气平衡器（路径 A/B 张力累加、`forcePositiveAt` / `forceNegativeAt`）**同源**：

- **默认**：留空（`null`）= 跟随房型（`resolveRoomTension(type)` 取 `tension.weights[type]`，未配置的房型为 `0`）；点「默认」按钮可一键清空回跟随。
- **自定义输入**：编辑器「张力」改为**自定义数字输入**（可填任意数值，如 `−1.5`），覆盖房型默认 —— 后续张力要**更精细划分**，因此不再限定 `−3 ~ +3` 的固定档位。
- **落地**：`buildRooms` 把解析后的**具体数值**写进 `RoomData.tension`，运行时与摘要都可直接读。
- **用途**：这是**后续改进「房间类型决定」**的输入 —— 让手工房也能参与「按张力梯度安排战斗/精英/安全房」的自动判定，而不是只看 `type`。

> ⚠️ 当前 `tension` **只作为数据维度落地**（编辑/存储/导出/运行时字段齐备），自动生成房仍按 `type` 取权重；把它接进「房间类型决定」属于后续改动。

### 6.2 手工房间库（`RoomLibrary`）——按「类型 + 通口」抽取

编辑器「保存到文件」把房间存进 `src/data/rooms.json`。`src/map/RoomLibrary.ts` 把它变成一个**可按维度抽取的房间库**：

```ts
import { listRooms, roomsOfType, pickRoom, patternOfRoom } from './map/RoomLibrary';

pickRoom({ type: 'combat', pattern: 'vertical', preferTension: 1, rand: Math.random });
// → 从「战斗房 + 上下通口」的候选里挑一间；同池多间时按 preferTension 取张力最接近者，再随机
```

- `listRooms()`：全部手工房（含 `pattern` 回填，见下）。
- `roomsOfType(type)`：按房型索引。
- `patternOfRoom(room)`：档案缺 `pattern` 时按 `exits` 现算（老档案向后兼容）。
- `pickRoom({ type, pattern?, preferTension?, exclude?, rand? })`：先按 `type` 取候选，再按 `pattern` 过滤（过滤后为空则退回该类型全部候选），可用 `exclude` 避免同层重复、用 `preferTension` 贴近当前运气平衡需要；无匹配返回 `null`（调用方回退程序化生成）。

> **这就是"同样类型也有不同体验"的实现落点**：同一 `type` + 同一 `pattern` 可以有多间手工房，靠各自的 `tension`（与布局）区分；生成楼层时按「类型 + 通口类型」抽取即可。
> 目前 `pickRoom` 是**数据层能力**（可无头测试）；把它接进 `MapGenerator` 替换自动生成房属于后续改动。

**通用密度上限**（自动生成房按内面积分档，见 `mapGeneration.content.density`）：内面积 ≤30 → 3 只、≤42 → 4 只、否则 5 只。手工房建议不超过同档，否则单房战斗过长。

> ⚠️ **火把不会自动来**：`ContentFiller.furnish()`（面积配额火把 / 长墙列柱 / 引导地毯）**只作用于自动生成房**。预制房需要你手工刷 `t`（火把）与 `p`（柱子），否则会偏暗偏空。

## 七、导出格式与入库

### 7.1 导出长什么样

```ts
// 房间编辑器导出 —— 图例见 src/map/PrefabMap.ts 顶部注释；设计规范见 docs/房间编辑器.md
const roomDef: PrefabMapDef = {
  floorId: 7,
  kind: 'normal',
  rooms: [
    { x: 2, y: 2, w: 7, h: 6, type: 'combat', name: '断桥守卫',
      entry: 'west', exits: ['west', 'east'], pattern: 'vertical',
      risk: 2, tension: 2, note: '中列屏障 + 火把' },
  ],
  rows: [
    '11111111111', // 门槽外圈（上）
    '11111111111', // 门槽外圈
    '11111111111', // 房间第 0 行 = 北墙
    '11100200111', // 中列 (x=3) 放怪 → 竖线屏障；西→东 主路径上必须打掉
    '11100200111',
    '00000200000', // 房间第 3 行 = 左右边界中点（西门 / 东门）+ 墙外自动补的走廊门槽
    '11100200111',
    '11111111111', // 北墙的对侧：南墙
    '11111111111', // 门槽外圈（下）
    '11111111111',
  ],
};
```

> 上面 `rows` 是**真实导出格式**（字符即图例）。房间矩形 `x=2, y=2`，宽 7 高 6；`rows` 每行 11 字符 = 7 + 2×2 门槽。西门在东/西边中点（房间第 3 行），墙外那 2 格 `00` 就是自动补的走廊门槽。

要点：
- `rows` 已经**包含门槽外圈**，所以 `rooms[0]` 的 `x/y` 恒为 `TEMPLATE_MARGIN (2)`
- `exits` 里的方向必须与 `rows` 里实际的门口一致（编辑器保证；手改会触发警告）
- `pattern` 由 `exits` 判定（`single` / `vertical` / `diagonal` / `tee` / `cross`），与 `type` 一起作为「从手工房间库抽取」的键；可由 `exits` 反推，手写可省
- `risk` 可省略（省略 = 不结算，宝箱 `rewardMul` 缺省 1）
- `tension` 可省略（省略 = 跟随房型，`RoomData.tension` 取 `mapGeneration.tension.weights[type]`）；显式标注才会出现在导出里

### 7.2 入库步骤

1. 点「复制代码」拿到 `roomDef`。
2. 存成模块文件（建议约定）：`src/map/prefabs/<名字>.ts`，`export const <名字>: PrefabMapDef = { ... }`。
3. 需要时载入：
   ```ts
   import { buildPrefabFloor } from './map/PrefabMap';
   import { myRoom } from './map/prefabs/myRoom';
   FloorManager.getInstance().enterPrefabFloor(buildPrefabFloor(myRoom));
   ```
4. 或从开发者控制台临时试：
   ```js
   __motaDebug.loadPrefab(pasteYourDef)
   ```

> 目前没有"关卡表/预制房注册表"——房间入库 = 存成模块并在需要的地方调用 `buildPrefabFloor`。若要做正式关卡，建议新建 `src/map/prefabs/index.ts` 汇总导出。

## 八、与运行时的关系

| 方面 | 自动生成房（`MapGenerator`） | 预制房（本编辑器） |
| :--- | :--- | :--- |
| 内容 | `ContentFiller` 按类型+深度自动填充 | **你手绘**，`ContentFiller` 完全不介入 |
| 校验 | `MapValidator` + `ContentFiller.validate` 就地铁封堵/补守卫 | 无自动校验：§5.4 的红线要自己守 |
| 火把/柱子 | `placeRoomTorches` + `placePillars` + `furnish()` | 手工刷 `t` / `p` |
| 风险收益 | `assignFloorRisk` 按侧室/精英/大房/深入/高层自动定档 | **显式标注** `risk`（编辑器「风险」下拉） |
| 通口类型 | 不落地 `pattern`（自动生成房按拓扑即时决定开口） | `RoomData.pattern` = **显式 `exits` 判定 → 网格门口反推**（`ExitPattern`）；已落地，供 `RoomLibrary` 抽取 |
| 张力值 | 由 `type` 查 `tension.weights` 累加进运气平衡器 | `RoomData.tension` = **自定义输入 → 房型默认**（`resolveRoomTension`）；已落地，待接入「房间类型决定」 |
| 走廊数据 | `CorridorData[]` 完整生成 | `corridors: []`（走廊直接体现在网格空地里） |
| 连接图 | 由生成器产出 | 由网格 **BFS 实测**（相邻但无通道的房间不会被误连） |
| `depth` / `onPathA/B` / `mountedOn` | 由路径规划器赋值 | 固定 `0 / false / null`（预制房不参与风险自动分层） |

## 九、测试与已知限制

**契约测试**：`node scripts/run-headless.mjs src/test/roomEditorTest.ts`（71 条断言）

覆盖：画布尺寸 / 默认墙体；**四个方向逐个端到端**（勾门 → PrefabMap 认出 → 入口可达墙外门槽）；入口方向写入 `fromDirection`；template → prefab → template 往返幂等；`exits` 缺省时可由网格反推；图例全覆盖（19 个字符 → 实体/地形）；三档宝箱；风险档结算到宝箱；**张力值**（缺省取房型权重 / 显式覆盖 / 往返 / `resolveRoomTension` 优先级）；无出口不产生门；**通口类型**（单口/上下/对角/T型/四方 分类、预设精确匹配、方向串、落地 `pattern`）；**房间库**（按类型 + 通口抽取、无匹配返回 `null`、`exclude` 生效）。

**已知限制**：

1. 编辑器只设计**单间房**（含门槽）。需要"房间 + 走廊"整体布局时，把多间房分别设计后再手工拼接 `rows`。
2. 图例字符是**离散固定**的：想要"某个特定怪物 id / 特定 Boss / 特定药水档"需导出后手改 `rooms`/实体（或后续扩展图例，如 `2` 改 `2a`）。
3. `B` 固定 `ancient_dragon`；`q` 取该楼层最高档药水。
4. 编辑器不写 `Kind`（`floorId` + `kind: 'normal'`）；Boss 层/塔顶层需导出后改 `kind`。
5. 预制房不参与风险**自动**分层，也不参与"同层怪物数值收敛"（`convergeFloorStats`）。
6. `RoomLibrary.pickRoom` 目前是**数据层能力**（已可无头测试）；`MapGenerator` 仍走自动生成，**尚未接入**「按类型 + 通口从手工库抽取」。
