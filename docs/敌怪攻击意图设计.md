# 魔塔RPG · 无尽之塔 —— 敌怪攻击意图设计（讨论稿）

> **状态：** 💬 讨论中（未定稿）｜**创建：** 2026-09-10
> **目的：** 为**微操战斗的逐回合操作**提供决策依据——让玩家在出招前知道"敌人下一步想做什么"。
> **关联代码：** `systems/BattleSystem.ts`（`BattleSession.stepManual()` / `monsterTurn()`）、`ui/BattlePanel.ts`、`src/data/monsters.json`、`src/types`
> **关联文档：** `docs/已完成.md` §1.4（战斗现状）、`docs/未完成.md` §二（Boss 词缀/状态效果）+ §三（数值平衡）

---

## 一、现状（代码实测）

**当前战斗是"无信息博弈"：**

| 项 | 现状 |
| :--- | :--- |
| 回合结构 | 玩家固定先手 → 怪物回合；`maxTurns = 60` |
| 怪物行为 | `monsterTurn()` **只有平 A**：闪避判定 → `max(1, 怪物攻击 − 玩家防御) ± 10%` |
| 微操动作 | `attack` / `potion` / `flee`（无防御、无技能） |
| 伤害公式 | 暴击 ×1.8、闪避归零、业火附加、嗜血按伤害回血、屠龙对 Boss 增伤 |

**结论：微操目前没有"策略空间"**——敌人每回合都是同一种攻击，玩家只要"血够就砍、血少就喝、不行就撤"，逐回合操作与托管结果几乎一致。**这正是意图系统要解决的问题。**

---

## 二、为什么需要"攻击意图"

1. **让微操有意义**：玩家能预判危险回合（重击/群攻/蓄力），从而选择喝药、硬扛或撤退。
2. **制造节奏与张力**：敌人在"蓄力—爆发"之间形成可读的节拍，而非线性换血。
3. **与 Boss 设计衔接**：Boss 词缀（`docs/未完成.md` §二·八）本质需要"技能"承载，意图是技能的可视化前置。
4. **差异化怪种**：现在怪物只有数值倍率差异，意图能让"史莱姆/蝙蝠/暗黑骑士"行为上一眼可辨。

---

## 三、设计目标

- **可读**：玩家一眼看懂敌人下回合的**动作类型 + 大致伤害**。
- **可决策**：意图必须能改变玩家的最优选择（否则形同虚设）。
- **确定性 vs 随机**：给出"预告"的同时保留适量不确定性（见 §4.4）。
- **兼容托管**：托管模式可选择忽略意图（保持现状公式）或同样按意图结算（数值一致）。
- **可扩展**：为将来的 Boss 词缀、状态效果留接口。

---

## 四、核心机制：意图系统

### 4.1 回合循环与意图时序（建议）

```
战斗开始 → 决定「本回合意图」并显示
  ↓
玩家行动（攻击 / 喝药 / 撤退 / [待定]防御）
  ↓
若玩家未撤退且敌人存活 → 敌人按**已预告的意图**执行
  ↓
回到顶部：决定并显示「下一回合意图」
```

> 关键：**意图在玩家行动前就要显示**，否则无决策价值。敌人下回合要做什么，本回合末即揭晓。

### 4.2 意图类型清单（草案）

| 意图 | 说明 | 威胁等级 | 备注 |
| :--- | :--- | :--- | :--- |
| **普攻** | 标准一次攻击（现状行为） | ★ | 默认意图 |
| **重击** | 单次高倍率攻击（×1.5~2.5） | ★★★ | 预告即"危险" |
| **连击** | 本回合攻击 2~3 次（每次较低） | ★★ | 对高闪避玩家不利 |
| **蓄力** | 蓄力一回合，下回合发动大爆发 | ★★★★ | 提供"打断/防御/撤退"窗口 |
| **防御** | 本回合减伤/进入格挡 | ★ | 建议输出低收益的窗口 |
| **治疗** | 回复自身生命 | ★★ | 玩家需抢输出或打断 |
| **增益** | 攻击/闪避/暴击 +X%，持续 N 回合 | ★★ | 拖久不利 |
| **减益** | 对玩家施加处罚（虚弱/破甲） | ★★ | 与状态效果系统联动 |
| **群攻/AOE** | 大范围伤害（对随从/Boss 战） | ★★★★ | 需玩家预警躲避 |
| **召唤/增援** | 召唤小怪 | ★★★ | Boss 专属 |
| **逃逸** | 低血时逃跑（玩家失去掉落） | ★ | 稀有怪 |
| **特殊/阶段** | Boss 血量阶段切换触发 | ★★★★★ | 脚本化 |

> 首版建议只做 **普攻 / 重击 / 蓄力 / 防御 / 治疗** 五种，够撑起微操决策即可。

### 4.3 意图预告的呈现（UI 建议）

- **图标**：怪物血条上方显示意图图标（剑=普攻、爆炸=重击、时钟=蓄力、盾=防御、十字=治疗）。
- **数值预告**：普攻显示"≈X 伤害"（基于当前攻防的**区间**，如 `38~46`），让玩家能算血。
- **危险配色**：重击/蓄力用红色强调；治疗用绿色。
- **文字一行**：如"暗黑骑士 举起重剑，蓄势待发……"。
- 落点：`ui/BattlePanel.ts` 顶部敌方面板；托管模式可隐藏。

### 4.4 意图的确定性（待讨论）

| 方案 | 说明 | 取舍 |
| :--- | :--- | :--- |
| **完全显示** | 直接预告"下回合重击" | 最利于微操，去掉博弈 |
| **区间/模糊** | 显示"可能重击或普攻" | 保留紧张感 |
| **权重隐藏** | 只显示图标族，数值隐藏 | 更硬核 |
| **推荐** | 普通怪**完全显示**；Boss 关键回合**完全显示**，随机回合**模糊显示** | 兼顾可读与张力 |

## 五、意图生成规则（草案）

### 5.1 普通怪
- 默认为**普攻**；按权重表概率插入其他意图（如 15% 重击、10% 蓄力…）。
- 连续两回合**不可重复强意图**（避免"重击连发"劝退）。

### 5.2 精英
- 提高重击/增益权重，血量低于 50% 时解锁"狂暴"（攻击 +X%）。

### 5.3 Boss（脚本化意图序列）
- Boss 采用**固定/半固定循环**（而非纯随机），如 `普攻 → 蓄力 → 大爆发 → 防御 → 召唤`，让玩家能"背板"。
- 血量阶段（如 70% / 40%）切换循环或解锁新意图。
- **与 Boss 词缀联动**：词缀可作为"被动规则"修改意图池（如"狂暴"词缀 → 血量<30% 时重击权重翻倍）。

## 六、与微操动作的联动（关键前置）

**当前玩家只有 `attack/potion/flee`。** 若意图只预告"敌人要打你"，玩家的应对仍然有限——建议讨论是否新增：

| 候选动作 | 作用 | 说明 |
| :--- | :--- | :--- |
| **防御 / 格挡** | 本回合受到伤害 −50~70% | 让"蓄力窗口"有意义；否则玩家只能喝药/撤 |
| **打断** | 对"蓄力中"的敌人造成伤害可打断 | 高风险高回报 |
| **道具/技能** | 使用战斗道具 | 长期扩展 |

> 若暂不新增动作，意图仍可用来说明"该喝药了/该撤了"，但策略深度有限。**这是本设计的最大开放问题（见 §十）。**

---

## 七、与既有系统的衔接

1. **Boss 词缀**（`docs/未完成.md` §二·八）：词缀=被动修正，意图=主动行为，两者互补；12 种词缀中"剧毒/冰霜/吸血鬼"等可直接转化为意图效果。
2. **状态效果**（`docs/未完成.md` §二·二）：减益/增益意图 = 施加状态；建议意图系统与状态效果同期设计。
3. **数值平衡**（`docs/未完成.md` §三）：意图会引入伤害方差（重击/蓄力），需在 `tierScale` 之外单独校准，避免"随机暴毙"。
4. **战斗预测** `forecast()`：可升级为"结合意图的危险度评估"。

## 八、数据与代码落点建议

**数据**（`src/data/monsters.json` 扩展，或新建 `intents.json`）：
```json
{
  "id": "dark_knight",
  "intents": [
    { "type": "attack",   "weight": 50 },
    { "type": "heavy",    "weight": 25, "multiplier": 1.8 },
    { "type": "guard",    "weight": 15, "reduce": 0.5 },
    { "type": "charge",   "weight": 10, "telegraph": "heavy" }
  ]
}
```

**代码落点**：
- `BattleSession`：新增 `currentIntent` 状态与 `rollIntent()`；`monsterTurn()` 改为**按意图执行**（而非固定平A）。
- `ui/BattlePanel.ts`：渲染意图图标 + 预估伤害区间。
- `types`：新增 `IntentType` / `MonsterIntent`。
- **托管兼容**：`runAuto()` 内部同样 roll 意图并执行，保证与微操数值一致（结算同源原则不变）。

## 九、平衡与风险

- **方差过大**：蓄力/重击可能"一回合秒杀"，需设**伤害上限**或"预告即可规避"的保底。
- **回合数**：加入防御/治疗意图会拉长战斗，逼近 `maxTurns = 60`，需评估。
- **托管体验**：托管下若意图导致随机死亡，玩家会觉得"不公平"——建议托管时对高威胁意图有**自动应对**（如危险回合自动喝药）。
- **可读性成本**：图标+数值需要美术与排版，属 UI 增量。

## 十、开放讨论点

1. **玩家是否新增"防御"动作？**（决定意图能否真正影响决策）
2. **意图完全公开 还是 部分模糊？**（§4.4）
3. **所有怪物都有意图，还是仅精英/Boss？**
4. **普通怪的意图是"每回合随机"还是"小型循环"？**
5. **托管模式如何处理意图？**（忽略 / 同样 roll / 危险自动应对）
6. **是否与状态效果、Boss 词缀同期开发？**（三者高度耦合）
